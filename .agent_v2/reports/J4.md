## Finding — P2 R2c: late auth switch is not sanitized at the final read-back boundary

Location: `apps/social-mobile/src/lib/postona-service-end-client.ts:70–71` (see the earlier identity filter at lines 63–66).

The new filter removes A's warning facts when the immediate post-mutation session read sees B or nobody. That protection is not applied after the following awaited preview. If its internal session check detects a later switch, end() converts that failure to RESULT_UNCONFIRMED and unconditionally attaches A's response/facts again. A successful preview bound to another context takes the same branch.

Independent reproduction, using the exact client and actual F5 PR193 lifecycle handlers with their synthetic world:
1. A gets a real preview, confirms, and actual F5 withdraw_postona completes: common account/login/Kabumori retained, Threads local_removed_remote_unverified, X uncertain count 2.
2. The immediate post-mutation session check still sees A, so the new filter passes.
3. Pause the final read-only preview response. Change the current session to B, or to null, then release the response.
4. preview() observes SESSION_CHANGED. end() nevertheless returns RESULT_UNCONFIRMED containing A's count-2 and Threads warning lines.
5. Two independent negative assertions expecting no previous-user warning both FAIL (different person / no person). The immediate-switch controls do suppress both warnings and pass.

**Scope and severity limit:** this is a failure of the task's client return-value isolation condition. It is NOT a demonstrated visible cross-user leak in the current screen. A separate test of the actual unchanged TSX screen confirms its captured user+session binding hides A's delayed result while B is shown. The OFF source flag also remains false. Keep both defenses; do not describe this as a production exposure.

Correction owner: POSTONA app G4/F4; recommended Opus5.5（高） for Claude or Sol（高） if explicitly assigned to Codex. Keep enough binding information from preview/session outcomes to distinguish these cases; do not simply drop all facts on every preview failure.
