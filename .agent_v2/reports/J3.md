## P2 findings

### R1a — stale count-only ACK can clear different later evidence

Location: `supabase/candidates/postona_x_publish_entitlement/002_x_service_end_saga_stop.sql:200–205` (signature at 187). `p_expected` binds a count, not the observed evidence snapshot/deletion generation. The subject advisory lock serializes operations but does not prevent ABA.

Independent reproduction: real candidate stop_x converts fake user's expired reservation R1 to uncertain; real purge/finalize commit and return count 1. Caller A reads it, caller/attempt B ACKs 1 and clears it. The same user reconnects in the fixture and completes a second **real** saga; a different reservation R2 is durably checkpointed and count is 1 again, with no tombstone remaining. A's delayed/retried old `ack(user,1)` succeeds and deletes R2, which A never observed. A later real endpoint retry returns clean 200 without the uncertainty field. Neither checkpoint set was inserted manually: both were produced by the actual SQL/TS flow; Auth/X and initial workspace setup were fake.

Correction: bind ACK to an opaque generation/snapshot digest or exact observed reservation set, validate under the same lock, and clear only that snapshot. Replayed ACK must not clear a later same-count set. Coordinate amended response/ACK contract with **F5**, whose PR193 currently sends only `p_expected`. Add a two-service-cycle same-count ABA regression.

### R3a — lease check precedes later row-lock waits

Location: `002_x_service_end_saga_stop.sql:94–98` and `:119–126`; parent `001_x_publish_entitlement_guard.sql:232` obtains `social_accounts FOR UPDATE` afterwards. The comment that all locks are already held is inaccurate: reservation sweep/account/authority rows can still wait.

Independent two-session reproduction: B holds the X account row with `SELECT … FOR UPDATE`. Fake deletion lease expires in 1s. A calls actual stop_x as service_role, passes the new clock check, then waits at the later account lock (`pg_stat_activity.wait_event_type=Lock` observed). After >1s, verify the lease expired and release B. A returns `stopped` and commits authority `revoked`, reservation `cancelled`, and a `service_stop` audit row. Expected: lease loss with no committed changes.

Correction: acquire relevant mutating row locks in deletion→workspace→row order before the final wall-clock authorization, and/or enforce an expired-lease exception rolling the entire operation back. Cover reservation-sweep and parent-stop waits, retaining valid-lease/concurrent controls. This is **F3's stop_x fence**, distinct from the inherited F5 hold issue.

### R1b — rollback empty check races with checkpoint COMMIT

Location: `supabase/candidates/postona_x_publish_entitlement/002_x_service_end_saga_stop_rollback.sql:8–16`. The empty SELECT is not serialized with writers through DROP. Rolling Edge code back first does not drain a SQL transaction already in flight.

Independent two-session reproduction: A runs actual stop_x and creates one checkpoint but has not committed. B executes the exact rollback file; its guard sees no committed evidence, passes, and actual DROP TABLE waits for A's table lock (lock wait observed). A commits. B resumes and drops the now-committed, unacknowledged evidence. Ordinary populated-table refusal passes, but this TOCTOU destroys evidence.

Correction: obtain the appropriate exclusive table lock **before** the emptiness check, recheck after waiting and refuse/roll back if evidence exists. Document draining in-flight work as well. Add writer-commits and writer-aborts controls; do not certify rollback preservation based only on the no-concurrency test.
