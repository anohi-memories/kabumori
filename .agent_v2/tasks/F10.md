## 目的
独立レビューで再現された管理基盤V3の欠陥を修正し、「登録したのに未反映／登録状態の誤判定／同時更新の消失」を防ぐ。現行F/Jと旧G/Hの運用は変えず、PR #229のV3候補コードとテストに限定する。

## 独立レビューでの必須修正
- **H1 lost update**: 同一task_id・statusでもTASK本文/期待blob SHA（または内容SHA256）が変わったらCONFLICT_SAME_SLOT。再計画で他者変更を上書きしない。期待SHAを指定していない古いクライアントはfail-closedにする。
- **H2 publish誤判定**: git push送信後の不明失敗、GitHub PATCHの5xx/切断/応答欠落はPUBLISHED_UNVERIFIED。既知の明示拒否と区別し、再送せずGET照合に限定。
- **H3 別slot並行**: gitの `incorrect old value` / `cannot lock ref` / `failed to update ref`、GitHubの422 Reference update failedをstale競合として扱い、最新baseで再計画。ただし同slot変更・試行上限・未知失敗は停止。
- **M1 archive完全性**: gh transportの終了コードとレスポンス完全性を検証。HTTP本文途中切断やGitHub blob SHA/size不一致時はarchiveを作らず、idleへ遷移させない。
- **M2 宛先制限**: root/ref/repoの明示allowlistと安全な既定値。任意 `.github/workflows` や現行 `.agent_v2`、外部repo/refの予期しないwrite禁止。
- **M3 非上書きとReport**: initはディレクトリ/TASK存在を確認、archiveは既存の任意ファイル存在でSTOP、CodexのReport欠落・task_id違いではarchiveやidle resetをしない。
- **M4 readback不確定**: GitHub compare/GET失敗（5xx含む）をREADBACK_MISMATCHと誤判定せずPUBLISHED_UNVERIFIED。自commitの検証と後続正当commitの区別。
- **Low L1-L7**: scopeを広げず、判定分類、先頭空白/UTF-8、attemptsの入力値、誤検知regex、redaction、余計な変更の検知、task_id/path sanitizationを可能な範囲で修正。変更しなかったものは理由をReportに記録。
