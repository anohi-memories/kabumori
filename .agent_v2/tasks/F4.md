## F4-owned implementation
1. Implement ServiceLifecycleProvider with a monotonic, user-scoped epoch, a typed hook `useServiceLifecycleEpoch(userId)`, and `bump(userId)` API (or `open(userId)` only if F5 agrees on precise return contract). Place provider above ServiceEnrollmentGate; place ServiceLifecycleSurface outside subtree remounted by gate. Prefer minimal scoped files/hooks and layout wiring and publish exact export paths/signatures in report for F5.
2. End success `ended`/`already_ended` from authoritative server for currently pinned user invokes bump(userId) exactly once. No bump on cancellation, preview, error, uncertain response or wrong user. Epoch must never encode entitlement verdict, bearer/session token, user preview, consent or secrets. F5 independently does server-authoritative entitlement readback and fail-closed; F4 must not implement that gate.
3. Preserve *same-user* service-end flow surface across session_id rotation, but invalidate old session-bound verification/consent/preview and require fresh reauthentication and preview as backend dictates (600s rule unchanged). On UID switch/sign-out, close surface and purge local stale user state; reject late async prior-user results and double-submit. No common-ID deletion from POSTONA-only termination.
4. Coordinate strictly F5-owned `apps/social-mobile/src/components/service-enrollment-gate.tsx` and gate tests as READ ONLY; do not change it. Align route/layout and end-screen tests only inside F4-owned files.
5. Establish typed mocked contract first, communicate exact signatures and branch ancestor to F5 coordinator so F5 can connect without inventing another provider. Then coordinate full F4/F5 integration: same user new session, wrong UID signal, late response, end success to closed gate, network failure fail-closed/manual retry, no automatic re-enroll, other-app entitlement unaffected.
