### 2. 契約（G4／G3 向けの確定仕様）
| 関数 | 形・権限 | 答え |
| --- | --- | --- |
| `private.account_lifecycle_brand_owner_epoch(p_brand_id text)` | `bigint`・STABLE・SECURITY DEFINER・`search_path=''`・**owner 専用**（anon／authenticated／service_role に EXECUTE なし。メンバーシップ経由でも不可。install が ACL を厳密にアサート） | epoch（1 以上）。条件: 引数が NULL でない／書き込みトリガーが存在し有効／**このセッションがトリガーを実行する**（`session_replication_role = origin`）／epoch の記録がある／owner 行が**ちょうど 1 つ**／記録した owner が実際の owner と一致。**それ以外は NULL（不明＝拒否）**。0 を返すことは決してない |
| `…_covered()` | boolean・owner 専用 | getter が使うカバレッジ判定 |
| `…_resync(p_brand_id text)` | bigint・VOLATILE・owner 専用（運用手順） | 不明を「変化」として扱い epoch を +1、実際の owner を記録し直す。カバレッジが壊れている間は拒否 |
- 初期世代は **1**。**決して戻らない**（履歴表に append-only のガード。減少・キー変更・delete・truncate は owner でも拒否）。履歴行は作業場所の削除後も残る（`brands` への外部キーなし）ので、再作成した同じ ID も続きから進む。
- 上がる条件: owner 行の INSERT／DELETE、`(brand_id, user_id, role)` が変わる UPDATE（旧か新が owner のとき。別の作業場所へ移れば両方が上がる）、TRUNCATE（記録済みの全作業場所）。owner 以外の行の変更・何も変えない UPDATE は動かさない。**owner の id のハッシュ・`max(updated_at)`・`now()`・`xmin`・G4 の代役は一切使わない**。
- ロック: 書き込みの行 → epoch 表の 1 行（AFTER トリガー内）。読み手はロックなし。同じ作業場所の 2 つの owner 行を逆順に触る 2 取引だけは 40P01 で片方が中断し得る（何も書かれず、戻らない）。
- ロールバック安全: epoch は同じ取引の中で更新されるため、取引・savepoint・処理された例外・失敗した文は何も動かさない。
- 呼び手の規則（G4／F3）: owner と epoch は**同じ文か同じ取引**で読む／記録時は NOT NULL を必須に／比較は `=`（NULL は fail closed）。`IS NOT DISTINCT FROM` を使うと不明＝不明が等しくなるので使わない（G4 の候補は `owner_epoch bigint not null` かつ `=`／`is distinct from` なので安全）。
- インストール＝照合: 既存の owner のある作業場所と既に記録された作業場所を現在の owner 状態と突き合わせ、食い違えば +1（無ければ 1 で作成）。ロールバックのファイルはトリガーと関数を消すが**履歴表は残す**（getter が消えるので必要とする側は拒否する＝安全側）。再 install は残った番号から続ける。トリガーを通さない書き込み（トリガー無効／replica ロール）は、記録した owner と実際の owner の食い違いとして**検出**し、getter が NULL を返す（トリガー無しで A→B→A を完結された場合だけは検出できない＝レビューとオブジェクト所有でカバーする前提）。
