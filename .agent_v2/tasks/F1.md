### 結論（設計書 §0）
1. 形: **同期 Edge Function `ai-ask` + 小さな DB 境界**（設定・同意・残り回数・TTL 15 分の再生キャッシュ）。G2 のジョブ方式は作法だけ踏襲（別テーブル・別 RPC。個別分析の日次枠と混ぜない）。
2. 認証: JWT → `/auth/v1/user` で毎回本人確定（`social-mobile-consult/logic.ts:175-210` と同じ）。リクエストに ID なし。保有・ニュース・市況は **ユーザートークン（RLS）** で読む。サービスロールは台帳と確定のみ。
3. 最小化: 外部 AI へは銘柄コード・社名・構成比・ニュースの Fact 通過済み `app_*_ja`・共通市況の要点のみ。数量・取得単価・目標価格・メモ・メール・ユーザー ID は送らない（損益額も V1 は送らない）。
4. 捏造防止: 証拠表（ID 付き）をサーバーが作り、**出典・時点はサーバーが証拠表から生成**。モデルは証拠 ID だけ返す。検証 V1〜V8（スキーマ・ID の存在・数値/銘柄の根拠・売買指示の遮断・鮮度）で fail-closed。
5. 費用: ゲート → 本人日次（DB・権威）→ G6 台帳（per_user 日次 `max_calls`・`max_usd_per_call`・全体 USD）→ プロバイダー側の多層。1回の試算 約 0.001〜0.07 USD（カタログ `verifiedOn: 2026-10-10` の単価からの試算・**要再確認**）。初期候補: 本人 10 回/日（初週 5）・全体 20 USD/日。
6. 冪等: `request_id = SHA-256(user_id ‖ clientRequestId)`。台帳が「送信済みの attempt は別の送信を許可しない」ため、送信後に応答を失った再試行は再生キャッシュが唯一の復元手段（無しなら再課金・D3）。
7. 契約: Phase A の `AskRequest` は変更なし。追加は `remainingToday`、失敗コード `consent_required` / `no_holdings` / `not_enrolled`、`get_ai_ask_status()`。`version` の扱いも明記。
