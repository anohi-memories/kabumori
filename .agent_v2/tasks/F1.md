## 契約の一致（F3正本との差分）
- F3 `SinglePostRequest` は `{socialAccountId, clientRequestId, text, consent:{confirmed:true,contentSha256}}`。本人はJWTからのみ確定。UIの `connectedAccountId` はselectorに過ぎない。`targetId` ↔ `clientRequestId` は同一試行のUUIDを保持し、二重押し/同意後再試行で新しいIDを作り直さない。新しいユーザーの送信意思でのみ新ID。
- 本文は確認画面の**そのままの文字列**でSHA256を算出する（空白や改行の暗黙整形禁止）。投稿同意 `confirmed:true` は画面で利用者が明示確認した操作以外で立てない。
- F3応答 `sent{xPostId}`→UI `published{providerPostId}` はサーバーの保存＋durable readbackが成立したときだけ。account/request ID等の取り違え・偽のsentは禁止。
- `failed`と`refused`は「確実に未投稿」を区別しつつ表示し、`pending`は投稿済みと扱わず同一IDによるサーバー状態確認/安全な再試行契約を明記する。`uncertain`は**自動再送しない**、X照合を依頼する。`unavailable`や通信例外は、実送信があり得るタイミングなら成功/確実未送信を断定せず、同一IDでのサーバー照合までfail-closed。オフラインmock成功は実X成功ではない。
- G1 `manual-publish-port.ts` はapp-onlyの型境界を維持し、既存 `provider-domain` import禁止テストに違反しない。F3 `single_post_contract.ts` と参照元の出典を明記してstate conversion/adapter testsを追加。不可逆な曖昧結果の記憶はprocess-localの限界を明示し、durable readback/再起動復旧はF3契約待ち。新SQLを追加しない。
- `getManualPublishPort()` は実接続しない／`UNCONNECTED_MANUAL_PUBLISH_PORT`維持／全画面送信disabled。強制onPressでも外部ネットワークへ出ない。サンプル結果はpreview限定、実投稿成功の表示は禁止。

### 契約の整合（F3 `single_post_contract.ts`／`single_post.ts`／docs §2 ↔ アプリ）
| 項目 | F3 の契約 | アプリ側 |
|---|---|---|
| 要求 | `{socialAccountId, clientRequestId, text, consent:{confirmed:true, contentSha256}}`（本人は JWT のみ） | `single-post-contract.ts` の `singlePostRequest`（キー集合を固定。user id なし） |
| `clientRequestId` | 小文字 UUID。再試行は**同じ ID** | 1 試行 = 1 UUID（`manual-` 接頭辞を廃止）。pending／unconfirmed の再試行は同じ ID のみ、新しい試行は新しい ID。別の本文・別アカウントとの共有なし |
| 本文とハッシュ | `contentSha256` ＝ 確認画面の本文そのものの SHA-256。サーバーは `sha256(convert_to(text,'UTF8'))` で照合 | 純 TypeScript の SHA-256。確認画面に出す正規化済みの文字列をそのまま計算・送信（確認後の整形なし）。`node:crypto` と一致（公開ベクタ・境界 0〜200 文字・絵文字・400 件の疑似ランダム）。アダプターも送信前に**再計算**し不一致はローカル拒否 |
| 投稿同意 | `consent.confirmed:true` ＝「この本文を、いま」の 1 回ごとの同意 | 確認画面のチェックボックスのみが生成。その本文・そのアカウント限定（照合コード＝ハッシュ先頭 12 桁を表示）。確認を閉じる・再試行・送信後に失効。同意なしは送信ボタン無効（強制 onPress でも不送信） |
| `sent` | サーバーが X の ID を保存し読み直しで一致 | `published`（数字の投稿 ID あり・attempt id 一致）だけが画面の「送信済み」。画面の `sent` を作るのは `resultOf` の 1 箇所（静的テストで保証） |
| `pending` | まだ送っていない（混雑／処理中）。同じ ID で再試行 | **pending**（「まだ送信されていません」）。uncertain にも sent にもしない。処理中の可能性があるため別の内容の送信をブロック。同じ ID の再試行か「Xで確認しました（破棄）」のみ |
| `failed` | 確実に未投稿 | **failed**（`rejected`）。次は新しい試行 |
| `uncertain` | 自動再送しない | **uncertain**。再試行ボタン自体なし。Xで確認→破棄のみ |
| `refused`（4xx） | 何も書かれていない | **refused**（コードのみ表示）。次は新しい試行 |
| `unavailable`（503／通信／不正応答） | 何も確定していない。同じ ID で再試行 | **unconfirmed**（「結果を確認できません」）。failed とは扱わない。同じ ID の再試行か破棄のみ。transport の例外もこれ（`TRANSPORT_FAILED`） |

### 追加した部品
- `manual-publish-port.ts`: 同意つき target と 6 種の outcome 型（`published／pending／rejected／refused／uncertain／unavailable`）。未接続ポートは `refused PORT_NOT_CONNECTED`（`published` を返さない）。
