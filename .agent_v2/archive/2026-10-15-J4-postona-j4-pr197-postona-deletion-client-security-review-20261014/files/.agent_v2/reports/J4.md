## P2 R1 — incomplete completion responses are promoted to success

Location: `apps/social-mobile/src/domain/postona-service-end.ts:88–95`, especially the missing-providers default at line 89; `src/lib/postona-service-end-client.ts:53–63`.

The result parser accepts `{ok:true,outcome:'ended'}`, defaulting missing providers to an empty object and missing remote/count fields to no warnings. The following account/entitlement preview cannot recover durable provider results or X uncertainty: F5's actual `handlePreview` does not return those facts.

Reproduction: run actual F5 preview → withdraw_postona with a connected Threads adapter and X outcome `{outcome:'done',unconfirmedPosts:2}`. F5 actually ends POSTONA, retains login/Kabumori, and emits Threads local_removed_remote_unverified plus count 2. At the synthetic transport boundary, replace just that completion body with `{ok:true,outcome:'ended'}`; leave the actual final F5 preview unchanged. The client returns ok=true and the completion sentence, count 0, no Threads warning, while the real fixture's durable facts still contain both warnings. This is a malformed-response fault injection, not a claim that F5 normally truncates its response.

The consistency check is also one-way: `providers:{x:'done'},remote_unverified:['threads']` is accepted despite no Threads result. Existing tests cover invalid provider values but miss absent mandatory fields and this inverse inconsistency.

Owner correction: POSTONA app owner G4/F4, or an explicitly assigned implementation slot (recommended Sol（高） if Codex). Validate variant-specific F5 success shapes before producing EndResult: fresh `ended` needs its actual provider summary; validate both directions of remote/provider consistency. Keep the documented optional fields for legitimate already_ended/not_registered cases. Where a response lacks the evidence needed to describe warnings, return RESULT_UNCONFIRMED or obtain an independently reviewed durable-result read-back; an entitlement-only preview cannot certify them. Add truncated-body and inverse-consistency regressions.

Reproduction B: let the post-mutation session check succeed, then fail the final preview transport. The count-2 warning survives, but the already-known Threads remote authorization warning is dropped.

Owner correction: same app owner, recommended Sol（高） if Codex.
