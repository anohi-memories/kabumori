## 6. 比較指標（取りこぼし重視）

重大ニュースの見逃しは、平均点より重く扱う。見逃し1件でも、平均が良ければよい、とはしない。

### 6.1 重要度判定

| 指標 | 定義・扱い |
|---|---|
| 重大ニュース見逃し件数 | 期待が important/most_important なのに no_post。**最優先。1件ずつ全件を人が確認する** |
| Recall | 正例のうち正しく検知した割合。95%上限（Clopper–Pearson）を併記し、点推定だけで順位付けしない |
| Precision | 検知のうち正しい割合。負例が少ないうちは参考値 |
| 過大判定件数 | 期待 no_post または important なのに most_important 等へ上げた件数 |
| 判定理由の妥当性 | 理由文が根拠（本文の事実）と整合するか。人が3段階で採点 |
| 本番との不一致 | 不一致を一覧にして人が確認する（一致率は正解率ではない） |

### 6.2 文章生成

| 指標 | 定義・扱い |
|---|---|
| 企業名 / 日付 / 金額 / 通貨 | 本文と一致するか |
| 事実関係・承認・決議状態 | 「承認済み」「撤回」等を取り違えていないか |
| 留保表現 | 「とみられる」等を断定に変えていないか |
| Fact/Voice 通過率 | 本番の Fact・Voice 検査をそのまま通る割合 |
| 改ざんプローブの検出率 | 既知の誤りを Fact が検出するか（6.4） |

### 6.3 API

実トークン、推定費用（OpenAI台帳と同じ単価表で計算）、応答時間（p50/p95）、再試行回数、エラー率（429/5xx/タイムアウト/スキーマ違反）。
費用は `usage` の実値から計算し、見積もりと実績を分けて記録する。

### 6.4 PR #116 の危険類型と改ざんプローブ

PR #116 が狙う失敗を、評価項目として明示した。実装は `tools/provider-compare/src/fact_probes.ts`（14テスト）。
Fact を通過した既存の投稿（recorded factStatus が passed）の最終テキストを機械的に書き換え、**正解（fail か pass）が分かっているプローブ**を作る。

| 変異 | 内容 | 期待 | 区分 |
|---|---|---|---|
| currency_swap | 通貨を取り違える（円↔ドル等） | fail | 主指標 |
| direction_flip | 負号・増減方向を反転（消失を含む） | fail | 主指標 |
| amount_swap | 指標と金額を入れ替える | fail | 主指標 |
| state_flip | 承認・撤回・決議の状態を反転 | fail | 主指標 |
| subject_swap | 主体（親会社↔子会社、情報源↔当事者）を入れ替える | fail | 主指標 |
| unit_equivalent | 同値の単位換算（億円↔百万円等） | pass | 主指標（過剰検知の測定） |
| hedge_removal | 留保表現を外して断定にする | fail | 探索的（正解の線引きが曖昧なため別集計） |

- 現在のプローブは20件（主指標17、探索的3。currency 4 / direction 3 / amount 3 / state 3 / subject 2 / hedge 3 / unit 2）。
- 判定は「見逃し（fail期待で通過）」と「誤検知（pass期待で検出）」を分けて記録する。
- プローブの正解はこちらが作った変異で決まるため、人手ラベルの代わりになる範囲は「Factの検出力」に限る。
- 主体不明瞭（subject_swap）は、元の文面に報道主体と当事者の両方が含まれる投稿が少なく、2件しか作れていない。追加ケースで増やす。
