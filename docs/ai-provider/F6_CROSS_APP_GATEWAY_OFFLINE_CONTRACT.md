## 0. 要約

- 共通の呼び出し口の 1 回の流れ（どの段も、断るときは費用も外への送信も 0）:
  1. 要求の形
  2. 認可の判定（G5 のもの。この口では**外から受け取る入力**）
  3. アプリの AI の機能の決まり
  4. 1 回の操作の費用の上限
  5. 呼び出しの番号と claim（二重実行の防止）
  6. 送信の試みごとに: 台帳の予約 → **認可の再確認** → 台帳の送信の確定 → 送信 1 回
  7. 台帳の確定、または不明（最大額）
  8. アプリの出力の検査
  9. 結果の記録 → 答え
- 要求は、モデル・provider・上限・利用者・主体を選べない。アプリの決まりと、G5 の判定が決める
- 同じ operationId でも、アプリ・利用者・ブランドが違えば別の呼び出し（番号・費用・保存した答えが混ざらない）
- テスト: 偽の部品で **11 PASS**（共通AI基盤の本体 `executeAiRequest` は本物）。わざと壊した写し **19/19 を検出**
- **すべて mock の PASS**。本物の Supabase・G5 の本物の判定・本番の台帳の行・保存の場所の本番の適用は NOT_VERIFIED

## 2. 契約の表

### 2.1 要求（アプリ → 共通の口）

| 項目 | 型・決まり | 誰が決めるか |
|---|---|---|
| `app` | `kabumori` / `postona` / `miseiro` | アプリ |
| `feature` | `^[a-z][a-z0-9_.]{1,63}$` | アプリ |
| `operationId` | `^[A-Za-z0-9][A-Za-z0-9_.:-]{7,127}$`。1 つの操作（例: 発言 1 回、レポートの 1 回）ごと | アプリ（利用者の端末でもよい） |
| `input` | 文字列。決まりの `maxInputBytes` まで | アプリ |
| `brand` | `{app, slug}` か `null`。**選ぶためのもので、権限ではない**（G5 の判定のブランドと一致しなければ断る） | アプリ |
| 上記以外のキー | **断る**（model、provider、上限、user、subject などを要求に入れられない） | — |

### 2.2 主体とブランド

| 主体 | 形 | 台帳に入るもの | 呼び出しの番号の材料 |
|---|---|---|---|
| system（運営の自動の仕事） | `{kind: "system", app}` | `subject_kind = system` | アプリ＋ system |
| user（人） | `{kind: "user", app, userId: 小文字の uuid, brand: {app, slug} \| null}` | `user_id` = その人。**ブランドの slug は台帳に入れない**（台帳の `brand_id` は uuid） | アプリ＋ userId ＋ brand |

- ブランドの slug（例: POSTONA の `u_` ＋ 16 進 24 文字）と利用者 ID を取り違えない。slug の形の値が利用者 ID に来る、uuid の形の値が slug に来る、別のアプリのブランド → すべて断る
- テナント ＝ SHA-256（アプリ, 判定の主体）。呼び出しの番号 ＝ `h5m2_` ＋ SHA-256（テナント, `app:feature`, operationId）。H5 bridge・#273 と同じ作り方

### 2.3 認可の判定（G5 → 共通の口。外から受け取る入力）

| 項目 | 意味 |
|---|---|
| `decision` | `allow` / `deny` / `unknown` / `pending`。**`allow` 以外は送信 0** |
| `subject` | 判定した主体（要求の本文からは決めない） |
| `generation` | 中身の見えない世代の値（例: 持ち主の epoch、利用権の版）。空なら `unknown` 扱い |
| `expiresAtMs` | 期限。過ぎていれば送信 0 |
| `reason` | 断った理由の固定のコード（任意） |

- `verdict(credential, {app, feature, brand})` と `recheck(prior)` の 2 つの口で受け取る。**送信の試みごとに、その直前に `recheck`** する。断る・保留・期限切れ・世代が変わる・主体が変わる・読めない → 予約を返し、送信 0（`AUTH_REVOKED_BEFORE_SEND`）
- G5 の今の設計（PR #279）との関係:
  - 案 A（今の推奨）: Edge の本人の確認＋持ち主の読み取り＋本人の利用権の読み取り＋送る直前の再確認。これを `verdict` / `recheck` として包めばよい
  - 案 B（一括の読み取りの RPC）: 未承認。**存在するものとして呼ばない**
- G5 の判定の外のこと（送信中に状態が変わっても止められない G-8、セッションの見えなさ G-2 など）は §3 の「保証しない」に書いた

### 2.4 アプリの AI の機能の決まり（アプリが定義 → 共通の口が使う）

| 項目 | 意味 |
|---|---|
| `app`, `feature` | 登録の鍵と一致しなければ「決まりなし」と同じ |
| `revision` | 決まりの版（2026-10-19 追加、GAP-3）。保存の控えの `policyVersion` になり、操作の中身（fingerprint）にも入る。無い・形が違えば「決まりなし」 |
| `ledgerFeature`, `logicalRole` | 台帳に数える名前 |
| `provider`, `model`, `reasoningEffort`, `maxOutputTokens`, `timeoutMs`, `maxAttempts` | **モデルと provider はここだけで決まる**（要求からは選べない） |
| `maxCostUsdPerOperation` | 1 回の操作のすべての試みの最大額。超えれば予約の前に断る |
| `maxInputBytes` | 入力の上限 |
| `subjectKinds`, `brandRequired` | 誰の呼び出しを受けるか |
| `systemInstructions`, `schema` | 指示と出力の JSON の決まり |
| `validate` | **必須**のアプリの出力の検査（無ければ「決まりなし」） |

- 決まりが登録されていないアプリ・機能（今の Miseiro など）は**断る**（fail closed）
- 値段・プラン・決まりの中身はアプリの持ち物。この契約は「使い方」だけ

### 2.5 費用・上限・台帳

| 段 | 内容 |
|---|---|
| 1 回の操作の上限 | 決まりの `maxCostUsdPerOperation` ≥ 試み 1 回の最大額 × `maxAttempts` でなければ、予約の前に `COST_DENIED` |
| 上限の枠 | 台帳の枠（アプリ・機能・主体ごと。#241 の「広い枠を作らない」決まり）。枠で断られたら送信 0 で `QUOTA_EXCEEDED`。台帳に届かない・送信を確定しない場合は送信 0 で `LEDGER_UNAVAILABLE`（GAP-2） |
| 予約 → 送信の確定 → 確定 / 不明 | 台帳の予約 → 認可の再確認 → 送信の確定（1 回だけ）→ 使用量が分かれば確定、分からなければ最大額で不明 |
| 費用と使用量の正本 | **台帳**。答えの audit（回数・概算額・確定か最大額か）は控え |

### 2.6 二重実行の防止

| 場面 | 答え | 送信 | 費用 |
|---|---|---|---|
| 初めての operationId | 送って記録 | 1 | 1 回 |
| 同じ operationId・同じ中身（再送） | 保存した答え | 0 | 0 |
| 同じ operationId・別の中身 | `OPERATION_REUSED` | 0 | 0 |
| 同時の 2 つ | 片方は `IN_PROGRESS` | 1 | 1 回 |
| 結果を記録できなかった | `UNKNOWN`。その後は `IN_PROGRESS`（復旧まで） | 1 | 1 回 |
| 別のアプリ・利用者・ブランドの同じ operationId | 別の呼び出し | 別 | 別 |

- 保存の場所（`ai_calls`、#249）は**本番に未適用**。本番で二重実行の防止が効くのは、適用の後

### 2.7 使用量の控え（audit）

`callKey`, `tenantTag`, `app`, `feature`, `model`, `attempts`, `estimatedCostUsd`, `costBasis`（`measured` / `includes_upper_bound` / `no_request`）。利用者 ID・ブランド・入力・出力の文は入れない。

- 保存の場所へは、共通の口がこれを**保存の場所の 9 項目**（`callId`, `tenantTag`, `feature`＝`app:feature`, `role`＝`logicalRole`, `model`, `policyVersion`＝`revision`, `attempts`, `estimatedCostUsd`, `costBasis`）に変えて渡す。再送のときは、すべての項目がこの呼び出しと今の決まりに合うことを確かめてから戻す。合わなければ `UNKNOWN`（2026-10-19、GAP-3。`docs/ai-provider/F6_GATEWAY_GAP_FIXES.md`）。

### 2.8 答えの error

| コード | いつ | 送信 | 費用 | 同じ operationId で送り直すと |
|---|---|---|---|---|
| `REQUEST_INVALID` | 形・キー・番号・ブランドの形・入力の大きさ | 0 | 0 | 同じ |
| `AUTH_UNAVAILABLE` / `AUTH_DENIED` / `AUTH_UNKNOWN` / `AUTH_PENDING` / `AUTH_EXPIRED` / `AUTH_SCOPE_MISMATCH` | 認可の判定 | 0 | 0 | 判定しだい |
| `POLICY_MISSING` / `POLICY_SUBJECT_DENIED` | 決まりが無い・合わない | 0 | 0 | 同じ |
| `COST_DENIED` | 1 回の操作の上限を超える | 0 | 0 | 同じ |
| `QUOTA_EXCEEDED` | 台帳の枠（`CALL_LIMIT` / `COST_LIMIT` / `PER_CALL_LIMIT` / 枠が無い） | 0 | 0 | 保存した答え |
| `LEDGER_UNAVAILABLE` | 台帳に届かない・送信を確定しない・その他の台帳の拒否（GAP-2） | 0 | 0 | `NOT_SENT`（同じ番号では送らない。新しい番号でやり直す） |
| `STORE_UNAVAILABLE` | 保存の場所に届かない | 0 | 0 | もう一度試せる |
| `IN_PROGRESS` / `OPERATION_REUSED` | §2.6 | 0 | 0 | — |
| `AUTH_REVOKED_BEFORE_SEND` | 送る直前の再確認で止まった（予約は返す）。2 回目以降の試みの前でも同じ（GAP-1） | 0（それより前の試みの分だけ） | 0（同上） | 保存した答え（`NOT_SENT`） |
| `NOT_SENT` | 何も送らずに終わった操作の再送 | 0 | 0 | 同じ |
| `PROVIDER_FAILED` / `OUTPUT_REJECTED` | AI の失敗・形の違う出力・アプリの検査で弾いた | 1 | 1 回 | 保存した答え（送り直さない） |
| `UNKNOWN` | 送った後の切断・時間切れ・記録の喪失 | 1 | 最大額 1 回 | 保存した答え（送り直さない） |

## 3. 信頼の境目ごとに、保証すること・しないこと

| 境目 | 保証する（この契約とテスト） | 保証しない（理由・担当） |
|---|---|---|
| G5 の認可の判定 | `allow` 以外・期限切れ・世代違い・主体違い・判定の主体と要求のずれは送信 0。送る直前に再確認 | 判定そのものの正しさ（G5）。セッションの見えなさ（G-2）、確定前の凍結の見えなさ（G-3）、送信中の状態の変化（G-8: 止められず、起きたまま記録） |
| アプリの決まり | 決まり無し・別のアプリの決まり・検査なしは断る。モデル・上限は決まりだけが決める | 決まりの中身・値段・プラン（各アプリ） |
| 共通AI基盤（provider） | 本物の `executeAiRequest` で、決まりのモデル・上限・試みの数だけ。結果の JSON の決まりの検査 | 本物の OpenAI / Anthropic の振る舞い（NOT_VERIFIED） |

| 保存の場所 | 再送・中身違い・同時・記録の喪失・テナントをまたがない（偽の保存の場所で確認） | 本番の適用（`ai_calls` は未適用）、復旧の仕事（Cron は無い） |
| アプリの出力の検査 | `validate` が false なら記録して `OUTPUT_REJECTED`、送り直さない | 検査の中身（各アプリ） |

## 6. G5 への受け渡し（Issue #266 に短く書いた内容）

- 共通の口は、認可を `verdict`（決定・主体・世代・期限）と `recheck`（送信の試みの直前）の 2 つの入力として受け取る。`allow` 以外・期限切れ・世代や主体の変化・読めないは送信 0
- 案 A（Edge の本人＋持ち主＋本人の利用権の読み取り）をこの 2 つに包めば足りる。案 B は呼ばない
- 世代の値は中身の見えない文字列（F5 が今作っている持ち主の epoch などをそのまま入れられる）
- AI のプラン・上限・予算・二重実行の防止・台帳は G6 の担当。利用権が active でも AI の判断ではない（#279 G-7 と同じ）
