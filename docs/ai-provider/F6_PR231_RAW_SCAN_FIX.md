## 1. 何が問題だったか

- #231 の検査は、字句解析でコードを読み、念のためにコメントとリテラルの中身を正規表現で読んでいた（`textEdges`）
- 字句解析で推測が要るのは「`/` が正規表現の始まりか、割り算か」だけ。ここを外させる合法なコードがあった
  1. `w.if(1) / ...`: プロパティ名の `if` を `if` 文と取り違え、`)` の後の `/` を正規表現と読んだ
  2. `const of = 2; of / ...`: 変数名の `of` を `for ... of` の `of` と取り違えた
  3. `function () { return 1; } / ...`: 関数式の `}` をブロックの終わりと取り違えた
  4. 逆向き: `case 1: { } /'/.test(...)` の正規表現を割り算と読み、`'` から文字列が始まったことにした
- 推測を外すと、本物の `import(...)` が「文字列や正規表現の中身」に入って見える
- その中身を読む `textEdges` は、正規表現の `matchAll` で重ならない一致だけを数えていた。中身の `"import/*"` から偽のコメントが始まって `*/('./types.ts')` までを 1 つの候補として読み、そのあいだの本物の `import("../ai_provider/mod.ts")` を飛ばした
- この結果、F6 と H5 の検査 16 件がすべて通った（本物のファイルで確認、§3）

## 2. どう直したか

### 字句解析から独立した読み取り（`rawEdges`）

- ソース全体（生の文字列）の `import` / `export` / `from` を一つずつ、それぞれ単独で読む
  - `import` の後ろに trivia と `(` があれば動的な読み込み
  - `import` の後ろに trivia と文字列があれば、中身を読まない読み込み
  - `from` の後ろに trivia と文字列があれば、import / export の句
- 候補は互いを飲み込まない。偽のコメントが別の候補の上にかかっても、その中の `import` は自分の位置で読まれる
- この読み取りは字句解析をまったく使わない。本物の読み込みは「キーワード → trivia → `(` か文字列」の形なので、字句解析がどう推測しても必ず見つかる
- 構文がコードのトークンから読めた読み込み（その `import` / `from` の位置）は飛ばし、構文の正確な名前を使う。それ以外の候補（コメントやリテラルの中、または推測を外したコード）はすべて足す。足すだけなので、検査は厳しくなる方向にしか動かない
- trivia のブロックコメントは「最初の `*/` で終わる」形の正規表現にした（`/*` から最短で閉じ、後戻りでも伸びない）

### 字句解析の推測を正しくした

- `x.if(...)` / `x.while(...)` などのプロパティ名は、制御文のキーワードとして扱わない
- `of` は `for (...)` の中でだけ演算子。ほかの場所では名前（割り算になる）
- `function` / `class` が式の位置にあるとき（`=` や `(` の後など）、その本体の `}` の後は割り算。宣言（文の始まり）なら、その後は正規表現になりうる
  - 文の始まりの判定に、三項演算子の `?` と `:` の対応、`case` / ラベルの `:`、モジュールのいちばん外側を使う
- `default` の後（`export default /re/`）と、`for await (...)` の `)` の後は正規表現
- 壊れた入力（閉じない文字列・テンプレート・正規表現・コメント、括弧の崩れ、知らない文字）は、これまで通りファイル全体を止める

### 変えていないもの

- 許可リスト（ファイル、届く先、名前）
- 計算した読み込み、別名の設定、シンボリックリンク、読めないファイル、存在しないファイル、大文字小文字、エスケープ、行の継続、中継、R1a / R1b / R1c の決まりとテスト
