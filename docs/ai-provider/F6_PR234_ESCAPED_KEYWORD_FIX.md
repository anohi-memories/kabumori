## 1. 何が問題だったか

- ECMAScript では、名前の文字を `\u0069`（= `i`）のように Unicode エスケープで書ける。キーワードには書けない決まりだが、Deno の変換は一部の形をそのまま動かす
- #234 の検査は、2 つの読み方を組み合わせていた
  - 字句解析と構文: エスケープした `import` をコードとして読めば「読めない」として止める
  - 生の文字列の読み取り（`rawEdges`）: `import` / `from` という**字面**だけを探す
- 字句解析は、TypeScript の型 `type T = { a: 1 }` の `}` の後の `/` を割り算と読んでいた。すると、その後の `'` から偽の文字列が始まり、エスケープした `import` が文字列の中に入って見える
- その結果、`type T = { a: 1 }` の後に `/'/.test("x"); void \u0069mport("../ai_provider/mod.ts"); /'/.test("y");` を置くと、F6 と H5 の検査 17 件がすべて通った（本物のファイルで確認。Report に書く）

## 2. Deno での実際の動き（2026-10-17、Deno 2.9.6、害の無い読み込み先で確認）

| 書き方 | `deno run` | `deno check` |
|---|---|---|
| レビューの形（1 行のまま） | 構文エラー | 構文エラー |
| レビューの形（型の後に改行か `;`） | **読み込みまで動く** | TS1260 |
| `\u0069mport(...)`、`\u{69}mport(...)`、`\u{0069}mport(...)`、6 文字すべてエスケープ | **動く** | TS1260 |
| `import { x } fr\u006fm "..."`、`export * fr\u006fm "..."` | **動く** | TS1260 |
| `i\u006dport(...)`、`\u0065xport * from`、`\u0069mport "..."`、`\u0069mport { x } from`、`export { x } \u0066rom` | 構文エラー | 構文エラー |

- TS1260 は「キーワードにエスケープ文字は使えない」
- deploy の前に型チェックが必ず走るかは確かめていない（NOT_VERIFIED）。だから検査は、動く形も動かない形も同じように止める

## 3. どう直したか

### エスケープした名前を、ほかの読み方と独立に調べる（`escapedKeywordEdges`）

- 生の文字列の中で、`\u` のエスケープを含む名前の並び（`\uXXXX`、`\u{...}`、大文字・小文字の 16 進）をすべて見つけ、解読する
- 解読した名前に `import` / `export` / `from` が含まれていれば、**無条件に止める**（「読めない」として扱う）
- コード・コメント・文字列・テンプレートを区別しない。区別が確かでない以上、文字の部分も許さない
- 字句解析も `rawEdges` も使わない。だから字句解析がどう推測を外しても効く
- エスケープを含む名前が 1 つも無いファイル（ほとんどすべて）では何もしない

### 字句解析の推測も正しくした

- `type 名前 = {` / `type 名前<...> = {` / `export type 名前 = {` の `{ ... }` は型。型を割り算することはないので、その `}` の直後の `/` は次の文の正規表現として読む
- これで、レビューの形のエスケープした `import` は、構文の側でも「エスケープしたキーワード」として読まれて止まる（二重に止まる）

### 変えていないもの

- 許可リスト（ファイル、届く先、名前）
- これまでの決まり（#219 R1、#222 R1a、#231 R1b / R1c、#234 の 4 つの反例、別名、計算した読み込み、シンボリックリンク、設定、読めないファイル）と、そのテスト

## 6. 残るリスク

- CI で動く静的な検査で、実行時の囲い（sandbox）ではない。`eval` / `new Function` / `Worker` の文字列、functions の外の設定、本番の deploy の設定は見ない
- 字句解析は完全な TypeScript の構文解析ではない。推測を外しても、`rawEdges`（字面の `import`）と `escapedKeywordEdges`（エスケープした名前）が見つけるか、ファイル全体が読めずに止まる
- 説明の文字列やコメントに import 風の文字やエスケープしたキーワードがあると止まる（運用上の制限。今は該当なし）
- deploy の前に型チェック（TS1260）が必ず走るかは NOT_VERIFIED
