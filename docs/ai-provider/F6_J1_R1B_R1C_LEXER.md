## 2. どう直したか

### 字句解析（`lexModule`）

- ECMAScript / TypeScript の字句のとおりに、ソースをトークンに分ける
  - 空白・改行・コメントは区切り（trivia）。**ブロックコメントは最初の `*/` で終わる**
  - 文字列、テンプレート（`${...}` の中はコードとして読む）、正規表現、数はそれぞれ 1 つのトークン。中身はコードとして読まない
  - それ以外は名前と記号
- だから、文字列の中の `"import/*"` がコメントを始めることはなく、import のトークンのあいだのコメントはただの区切りになる
- 推測が要るのは「`/` が正規表現の始まりか、割り算か」だけ。いつもの決め方に従う
  - 正規表現: 演算子の後、`return` などのキーワードの後、`if` / `while` / `for` / `with` の `)` の後、ブロックの `}` の後
  - 割り算: それ以外（名前・数・文字列・`)`・`]` の後、TypeScript の `x!` の後）
- 壊れた入力は、ファイル全体を「読めない」として止める
  - 閉じない文字列・テンプレート・正規表現・コメント、括弧の対応の崩れ、知らない文字

### 構文（`moduleEdges` / `parseClause`）

- トークンから、モジュールを読み込む形だけを文法どおりに取り出す
  - `import ... from "x"`（既定・名前つき・名前空間・`type` つき・文字列の名前）
  - `import "x"`、`import("x")`（文字列でない引数は「計算した」として止める）
  - `export * from "x"`、`export * as ns from "x"`、`export { ... } from "x"`、`export type { ... } from "x"`
- 読み込まないものは数えない
  - `export { a }`（from なし）、`import.meta`、`x.import`、`{ import: 1 }`
- 文法に合わないもの、エスケープで書いた `import` / `export`（モジュールでは構文エラー）、TypeScript の `import x = require("y")` は、「読めない」として止める（行き先が分かれば追う）

### 文字の部分の念のための読み取り（`textEdges`）

- コメントと各リテラルの中身は、#222 までの正規表現の読み方で別に読む。結果は足すだけで、減らさない
  - `/` の推測を外すと、コードが文字列や正規表現の中身に入って見える。そうなっても読み込みを見落とさないため
- 代わりに、説明の文字列やコメントに `import('./x.ts')` のような文字があると、止める側に倒れる（今の functions には無い）

### 変えていないもの

- 許可リスト（ファイル、届く先、名前）は広げていない
- 計算した読み込み、別名の設定、シンボリックリンク、読めないファイル、存在しないファイル、大文字小文字の違い、エスケープ、行の継続、中継の決まりは、そのまま（テストもそのまま通る）

## 4. 残るリスク
