## 1. What G5 adds: R1-MVP (`supabase/candidates/postona_personal_mvp_auth/parts/M20_personal_authorization_verdict.sql`)

It is part of the personal MVP profile (G5-46), installed after M10 in the same transaction (`MVP_INSTALL.sql`, regenerated by the builder).

**What stays the same as the reviewed R1:**
- the name, signature and arguments: `public.common_account_authorization_verdict(p_app text, p_feature text, p_brand_id text) → jsonb`;
- the **v1 wire** (8 keys);
- D1's strict claims;
- every reason and its order for the subject, the question, the session, the account and the x_autopost service.

**What differs:**

| Step | Reviewed R1 (full profile) | R1-MVP |
| --- | --- | --- |
| Workspace | brand row, caller's role, single owner, **owner epoch** | `p_brand_id` = the caller's derived id, and S2-3 = `own`. Another or an absent id → `deny BRAND_ACCESS_DENIED` (same answer). Two owners → `unknown WORKSPACE_OWNER_UNKNOWN`. Any other S2-3 refusal (second member, another owned brand) → `deny OWN_WORKSPACE_CONFLICT`. |
| Generation | — | GC false → `unknown SERVICE_GENERATION_UNAVAILABLE` |
| Allow token (`owner_epoch` field) | `g5oe:<owner epoch>:<lifecycle_version>` | **`g5pv:<lifecycle_version>`** |
| Shipped ACL | owner + `authenticated` | **owner only** (see §3) |

**The token** `g5pv:<n>`:
- `n` is `common_accounts.lifecycle_version` (decimal, `[1-9][0-9]{0,18}`).
- P1's trigger sets it to old + 1 on **every** update of the account row, and on every entitlement change. GC checks that this trigger is exactly P1's on every call, and the answer is `unknown` otherwise.
- So, per person, **the token strictly increases and an old token never comes back**: stop, restart, end, lock and deletion each move it.
- It is bound to the person (G6 hashes it with the user and the session ref).
- It carries no owner identity. The owner is fixed by the derived id and S2-3, which are checked on every call.

## 2. Measured (PG17.11, a world WITHOUT #457, fake data; `supabase/tests/postona_personal_mvp_auth_pg_*`: 7 / 7 ×3, R1-MVP mutants 10 / 10)

**R1-MVP, as authenticated** (the reviewed ACL granted in the TEST WORLD only):
- **allow:** the 8-key wire, with `owner_epoch = g5pv:<lifecycle_version>`, `entitlements = ["postona:x_autopost"]` and the exact scope.
- **refusals:**

  | Case | Answer |
  | --- | --- |
  | anonymous, or `is_anonymous` missing | `AUTH_REQUIRED` |
  | ended session | `SESSION_EXPIRED` |
  | unknown session | `SESSION_REVOKED` |
  | another person's workspace, or an unknown one | `BRAND_ACCESS_DENIED` |
  | a second member | `OWN_WORKSPACE_CONFLICT` |
  | a second owner | `unknown WORKSPACE_OWNER_UNKNOWN` |
  | suspended | `SERVICE_SUSPENDED` |
  | being ended, or an end operation while the entitlement row reads active | `SERVICE_DELETION_IN_PROGRESS` |
  | tampered generation triggers | `unknown SERVICE_GENERATION_UNAVAILABLE` |

- **end → restart:** a new token, greater than the old one.
- `anon` / `service_role`: permission denied.
- **As shipped** (no grant): `authenticated` is denied too.

**RESIDUAL:** an owner change undone before the call (A→B→A, possible only for service_role or the owner) still gives `allow` with the same token, as for MV (G5-46).

**G6, real code (PR #500 transport + authority port):**
- **Unchanged:** the MVP allow becomes `unknown OWNER_EPOCH_SHAPE`. **Today's G6 never allows a g5pv token (fail-closed).**
- **With only the contract's `OWNER_EPOCH` line** (test-only copy):
  - `allow`;
  - a recheck with nothing changed gives the **same generation**;
  - after end → restart, the recheck generation **moves**, so the gateway stops the prior call;
  - after a suspend, the recheck is `deny SERVICE_SUSPENDED`.

**Rollback:**
- the MVP rollback refuses while a function calls R1-MVP (`R1MVP_ROLLBACK_PRECONDITION_CALLERS`);
- it never drops the full profile's reviewed R1 (`R1MVP_ROLLBACK_PRECONDITION_NOT_MVP`);
- otherwise it restores the exact catalog.

## 3. The interface contract for G6 (one place; G6-20 can proceed on it independently)

| Item | Contract |

| Response | the v1 wire, unchanged keys. In the MVP profile a workspace-scoped allow carries `owner_epoch` = `g5pv:<n>` instead of `g5oe:<e>:<n>` |
| **G6 change (the only one)** | `supabase/ai_gateway/authority_port.ts`, `OWNER_EPOCH`: accept `^g5pv:[1-9][0-9]{0,18}$` as well. **Recommended:** pin the expected form by configuration (`full` → only `g5oe`, `personal` → only `g5pv`), so a deployment cannot be answered in the other profile's form. |

| Ledger / provider denial (G6-18 / G6-20) | Bind the ledger entry to the generation (the token is part of it). **Deny the provider call and refuse the ledger commit** when the recheck is not `allow` or its generation differs: end, restart, suspend, session end, second member / owner, wrong workspace, GC. |
| New reasons G6 may see | `OWN_WORKSPACE_CONFLICT` (deny), `SERVICE_GENERATION_UNAVAILABLE` (unknown). The others are R1's existing ones. G6 already passes any token-shaped reason through, and maps anything unexpected to `unknown`. |
| Work without the person (no JWT) | R1 is not for it. In the MVP, use G5's owner-only MV `private.postona_personal_worker_verdict(user, workspace, 'x_autopost', n)` from an **owner-owned SECURITY DEFINER** function, with `n` parsed from the token. There is **no grant**. |
| EXECUTE | R1-MVP ships **owner-only**. Wiring needs the reviewed R1 ACL (`EXECUTE` to `authenticated`, nothing to `anon` / `service_role`). That grant is the **one decision of the bundled review**, not of this candidate. |
| Migration order | 1. G6 accepts `g5pv`, pinned to `personal`.<br>2. G5 MVP profile applied, with the R1 ACL decided.<br>3. Wire.<br>Until step 1, every MVP allow is G6 `unknown` (fail-closed, measured). |

## 4. G3 / G4 consistency (read-only)

- **The token is the same counter** G3 stores at reservation create and MV checks at send (G5-46 contract): `common_accounts.lifecycle_version`.
- **The SNS connection generation is NOT in the AI token**, because AI text uses no SNS connection. For posting it stays with G3 / G4:
  - G3 `postona_x_resv` `x_credential_generation` (PR #541, `006`);
  - G4 `postona_g4_x_oauth.connections.connection_epoch` (PR #533, `001`).
- **P-4** (does sign-out stop pending jobs) is **not decided** here. R1 itself is session-bound: a session end denies.
