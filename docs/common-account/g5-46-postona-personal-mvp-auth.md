## 1. Verdict on PR #457 for the MVP

**PR #457 can leave the MVP-required set for every X / Threads posting and connection path** (person entries, scheduled jobs, cancel / receipt). It is replaced by the new profile in §2, measured below.

**It stays required today for one MVP path: G6's AI text via R1.**
- R1's body reads `account_lifecycle_brand_owner_epoch`, and so do its installs (R0 / R1 / SV / D1 check `owner_epoch_exposure`).
- G6's port refuses a workspace-scoped allow without `owner_epoch = g5oe:<epoch>:<lifecycle_version>` (`supabase/ai_gateway/authority_port.ts:132-133`, PR #500).

To drop #457 there as well, one contract change is needed (§5 G6 row):
- G5: an R1 variant whose workspace token is the personal generation;
- G6: accepting that token;
- one bundled review of both.

That is **not** done here.

## 2. What G5 ships for the MVP (new, G5-owned): `supabase/candidates/postona_personal_mvp_auth/`

`MVP_INSTALL.sql` is **one transaction**, generated by `supabase/tests/postona_personal_mvp_auth_build.py`. `--check` re-derives it byte for byte from blob-pinned reviewed parts.

| Gate | Source | Role in the MVP |
| --- | --- | --- |
| S2-2 `private.postona_personal_session()` | bundle part 60, verbatim | a person entry needs a live, non-anonymous session (`sub` = `auth.uid()`) |
| S2-1 T13 `private.account_lifecycle_assert_active_service_write(uuid,text)` | bundle part 70, verbatim | a person write needs an active service; anonymous is refused |
| S2-3 `private.postona_personal_workspace_eligibility(uuid)` | bundle part 50, **the predicate only** (lines 64-95, 98-143), verbatim | the workspace is the person's own: derived id, exactly one membership (the person as owner), no other owned brand |
| GC `private.account_lifecycle_generation_covered()` | bundle part 10, **GC only** (lines 98-130), verbatim | the service generation (`lifecycle_version`) is moved only by P1's two triggers |
| **MV** `private.postona_personal_worker_verdict(uuid,text,text,bigint)` | **new**: `parts/M10_personal_worker_verdict.sql` | a job made for (person, workspace, generation V) may still run: derived workspace, S2-3 `own`, P5 state `active`, generation still V, GC true |

Every gate is **owner-only (no grant)**, the lifecycle owner's, and unreachable from any API role (install postcondition).

**Prerequisites** (`MVP_PREREQ_*`):
- P1 lifecycle chain;
- P3: no API role holds TRIGGER, and anon / authenticated hold **no INSERT / UPDATE / DELETE / TRUNCATE / REFERENCES** on `brand_memberships`. This is stricter than G5-42, because the MVP relies on no person being able to change memberships;
- P4 auth;
- not a superuser.

**No owner epoch.** `MVP_ROLLBACK.sql` (one transaction) drops MV, S2-3 and GC (each refuses while called), then bundle R60 / R70 verbatim.

**Left out (B, owner-transfer only, or needing #457):**
- R0 `common_account_bootstrap_verdict`;
- R1 `common_account_authorization_verdict`;
- SV `account_lifecycle_session_verdict`;
- D1;
- W1 / W2 `*_worker_brand_verdict`;
- every `account_lifecycle_*owner_epoch*` function and table of `supabase/candidates/common_account_brand_owner_epoch/001` (#285 → #303 → #457).

**The two profiles exclude each other** (measured):
- the MVP and the G5-42 migration candidate each refuse on top of the other;
- switching = rollback, then install the other;
- without #457 only the MVP installs (`MIGRATION_PREREQ_P2_OWNER_EPOCH_MISSING`).

## 3. Fail-closed replacements for each MVP event (measured on PG17 in a world WITHOUT #457, `supabase/tests/postona_personal_mvp_auth_pg_*`, 5 / 5 ×3)

| Event | Person entries (create / cancel / connect) | A job running without the person (MV) | Owner of the rest |
| --- | --- | --- | --- |
| Signed out / session ended | S2-2 not `active` (ended, unknown, anonymous, `is_anonymous` missing, no claims) | **not MV's business:** a scheduled post is the person's, not the session's (MV answers `active`). Whether sign-out cancels pending jobs is **P-4 (user)**; if yes, G3 binds the session at create and G5's S2-2 rule applies at send. | user (P-4), G3 |
| Service suspended / being ended | T13 refuses | `SERVICE_NOT_ACTIVE` / `SERVICE_DELETION_IN_PROGRESS` | — |
| Ended, then restarted | — | `SERVICE_GENERATION_CHANGED` (`lifecycle_version` moved: measured end → reactivate) | — |
| Account deleting / locked | T13 refuses | P5 state code | — |
| A second member or owner on the workspace | S2-3 `OWN_WORKSPACE_CONFLICT` | `OWN_WORKSPACE_CONFLICT` / `WORKSPACE_OWNER_UNKNOWN` | — |
| A job pointed at someone else's workspace | — | `NOT_PERSONAL_WORKSPACE` | — |
| Generation triggers tampered | — | `SERVICE_GENERATION_UNAVAILABLE` | — |
| SNS disconnected / reconnected after the job was made | — | not visible to G5 | **G4:** connection epoch / credential generation. **G3:** bind it at create, compare at send. |
| Duplicate send | — | not visible to G5 | **G3:** lease / fencing (existing) |
| Concurrency | — | READ COMMITTED: a job holding its transaction sees a service end committed by another session at its next check (measured: `active` then `SERVICE_DELETION_IN_PROGRESS`). **Check MV in the send transaction, right before the send.** | G3 |

**RESIDUAL, stated:**
- An owner change that is **undone** between a job's creation and its run (A→B→A) is invisible to MV (measured: `active`).
- In the MVP no API role can write `brand_memberships`: authenticated has SELECT only, and the install refuses otherwise. **service_role** and the owner still can.
- Closing that without an epoch means no server path may write a personal workspace's memberships except creation (G4 begin) and the deletion saga. That needs a write-path inventory (G3 / G4 / H5) and is **not** enforced here.
- An immutability guard on `brand_memberships` would be a separate, reviewed change. It is not attempted here.
