# 市場異常 → ニュース逆引き構想（N1）

- 作成: 2026-09-28（N1 調査。設計のみ。実装・DB・Cron・production 変更なし）
- 関連: [news_acquisition_architecture.md](news_acquisition_architecture.md) / [news_cost_estimate.md](news_cost_estimate.md)
- 先行調査: docs/news-coverage/SHADOW_COVERAGE_GAP_RESEARCH_2026-09-20.md §Abrupt-market-move design（本書はその具体化。方針は同じ：価格検知とニュース収集は分離し、データ品質ゲートを必須にする）

## 0. 結論

1. 構想（市場異常 → 記事プールを再検索 → 無ければ Web Search）は**コスト削減効果が大きい**。Web Search を「何か起きているかもしれないから毎時探す」から「**値動きで何か起きたと分かった時だけ、しかも記事プールで説明できない時だけ**」に変えられる。
2. ただし**最大の制約はデータの権利**。2026-09-28 時点の調査では、**1〜15分足を商用アプリの内部トリガーとして無料・合法に使えるデータ源は見つからなかった**。先物（CME: WTI・S&P/Nasdaq 先物・金・銅・日経先物）と VIX（Cboe）は、**非表示の内部利用でも取引所ライセンスの対象**。
3. 現実的な段階案:
   - **段階1（無料・日次）**: FRED / 米財務省 / EIA / ECB 参照レートの日次値で「前日比の急変」を検知 → 翌朝の取りこぼし検査（benchmark の R3 入口）に使う。リアルタイム性はない。
   - **段階2（無料・日中の代替シグナル）**: **記事プール内の「ニュース量の急増」**（同一 entity・同一語の出現数が平常比で跳ねる）を異常シグナルとして使う。価格ではないが、権利問題がなく、速報性がある。
   - **段階3（有料・最小構成）**: 米国上場 ETF（USO/BNO/FXY/IEF/SPY/QQQ/SMH/GLD/CPER/VIXY 等）の日中価格を代替指標として取得。最安候補は Tiingo（商用プラン、価格は要確認）。実値の先物・VIX・日経を使うなら CME/Cboe/日経の個別見積りが必要（要確認）。
4. 既存の `personalized-reports` は Yahoo Finance の非公式 chart API を使っている（MIC 設計書 Phase 1A 追記）。Yahoo の規約は書面許可のない商用利用を禁じているため、**異常トリガーの根拠に Yahoo を新たに使うことは推奨しない**（既存利用の扱いは別途判断事項として報告のみ）。

## 1. 対象指標とデータ源

| 指標 | 何を示すか | 無料（日次） | 日中（候補） | 権利上の注意 |
|---|---|---|---|---|
| WTI | 原油急騰・供給障害 | FRED `DCOILWTICO`、EIA API（スポット） | ETF 代替 USO（有料 API） | CME 先物の実値は ILA 契約（内部利用でも） |
| Brent | 中東・海上輸送リスク | EIA API（国際） | ETF 代替 BNO | ICE の実値は有償 |
| USD/JPY | 介入・日銀・金利差 | ECB 参照レート（Frankfurter、1日1回）、FRED `DEXJPUS`（週次公表で数日遅れ） | FX ベンダー（有料、要確認） | FX は取引所データではないためライセンスは比較的軽いが、ベンダー規約次第 |
| 米10年金利 | 金融政策・インフレ | FRED `DGS10`、米財務省 利回り曲線（日次） | ETF 代替 IEF/TLT | 財務省データは公的 |
| 日経先物 / 日経平均 | 日本株全体 | FRED `NIKKEI225`（第三者権利あり→内部のみ・表示不可） | 情報ベンダー契約が必要（日経：自社内の指標利用は許諾不要だがデータ取得にはベンダー契約） | 日経は ©表示条件、20分以上遅延の第三者提供は許諾要 |
| VIX | リスクオフ | FRED `VIXCLS`（第三者権利→内部のみ） | ETF 代替 VIXY | Cboe は表示/非表示で別料金 |
| 金 | 地政学・リスクオフ | —（LBMA 系は権利あり、要確認） | ETF 代替 GLD | CME 先物は ILA |
| 銅 | 景気・中国 | — | ETF 代替 CPER | 同上 |
| 半導体指数 | 半導体・AI | — | ETF 代替 SMH/SOXX | SOX 指数そのものは Nasdaq の指数ライセンス（要確認） |
| S&P500 / Nasdaq | 米国株全体 | FRED `SP500`（権利あり） | ETF 代替 SPY/QQQ | 同上 |

- ETF 代替は**米国の取引時間（日本時間の夜）しか動かない**。日本時間の日中の急変（為替介入・日本株急落）は捉えられない。日本時間日中は段階2（ニュース量急増）と FX ベンダーで補う必要がある。
- FRED の系列ごとに権利表示（Public Domain / Copyrighted: citation required / 第三者権利）が違う。**系列単位で確認して source 定義に持つ**。

## 2. 閾値の考え方

先行調査の方針どおり、**サンプルから閾値を決め打ちしない**。以下は「キャリブレーションの初期候補」であり、過去データで誤報率・見逃し率を測ってから確定する。

| 指標 | 初期候補（仮） | 評価方法 |
|---|---|---|
| 共通 | 直近20営業日のリターン分布に対する z スコア ≥ 3（窓: 15分 / 60分 / 日次） | 過去1〜2年の日中データで、重大ニュース日との一致率を測る |
| WTI / Brent | 60分で ±3% 前後、日次 ±5% 前後 | 同上 |
| USD/JPY | 30分で ±1円前後（介入型の急変） | 過去の介入日（公表日）で検証 |
| 米10年金利 | 日中 ±10bp 前後 | 指標発表日を除外した上で評価 |
| 日経先物 | 15分で ±1%、日中 ±2% 前後 | |
| VIX | 日次 +20% 前後 または水準の急上昇 | |
| 金 / 銅 | 日次 ±2〜3% 前後 | |
| 半導体（SMH 等） | 日次 ±3% 前後 | |

- **指標発表・会合など予定されたイベントの時間帯は閾値を上げるか、原因を「予定イベント」として自動で紐付ける**（予定イベントは原因が既知なので Web Search 不要）。
- データ品質ゲート（先行調査と同じ）: 観測時刻・取得時刻・取引時間区分・単位・出典 URL が揃わないデータは使わない。欠損・遅延時は `price_trigger_unavailable` を記録し、何もしない（既存経路に任せる）。

## 3. 逆引きフロー

```text
異常検知（instrument, window, 変化率, 検知時刻）
   ▼
① 予定イベント照合   経済指標・会合カレンダーに該当？ → 原因=予定イベントで終了（AI・検索なし）
   ▼
② 記事プール再検索   直近 N 時間（例 6h）のクラスタを instrument 関連語で検索
                     （WTI → 原油/OPEC/ホルムズ/製油所/パイプライン/制裁/イラン/ロシア…）
   ├─ 該当クラスタあり → 「原因候補」として既存の判定待ちへ（重要度は既存の judgement に任せる）
   ▼ 該当なし
③ 関連 source の臨時巡回   instrument 別の優先 source を即時 1 回ずつ取得
                           （WTI → EIA/OilPrice/Rigzone/gCaptain/Maritime Executive/White House・State…）
   ├─ 見つかる → ②へ
   ▼ 見つからない
④ 限定 Web Search 1回   instrument × 時間窓 × 関連語で検索（日次上限・instrument別クールダウンあり）
   ▼
⑤ 記録               見つからなかった場合も reason code（no_cause_found）で残す
```

- 1回の異常で Web Search は**最大1回**。同じ instrument の再発火は**クールダウン**（例 60分）。
- 段階2（ニュース量急増）も同じ②〜⑤に流す。この場合は「急増した entity」が検索語になる。

## 4. ニュース取得費用への効き目（見込み）

- 現行（AUDIT_AND_PLAN, 2026-09-19 時点）: breaking_market の Web Search は 48時間で 366回、有効候補5件（空振り 99%）。その後 cost-optimization 側で頻度・方式の見直しが進行中のため、**現在値は本書では断定しない**（cost-optimization 側の usage metering の実測値を参照すること）。
- 異常トリガーは「何も起きていない時間の検索」をゼロにする仕組み。異常の発生頻度は平常日で1日0〜数件、ニュースの多い日で10件前後と想定（**要実測**）。そのうち記事プールで説明できないものだけが Web Search になるため、**異常由来の Web Search は1日0〜5回程度**と見込む（仮定。news_cost_estimate.md で幅を持って試算）。
- ただし段階1（日次）はリアルタイムの発見には効かない。**日中の Web Search 削減に効くのは段階2・3**。段階3は有料データ費用が別途かかる（要確認）。
