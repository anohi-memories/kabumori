## 2. 何が本物で、何が偽物か

| 部分 | 区別 |
|---|---|
| 画面・保存の処理 | **製品のコード**（§1 の違いだけ） |
| ログイン | **手元の本物の GoTrue**に画面から入った |
| 一覧・変更・取消 | **手元の本物の Kong・Edge の双子・Postgres**。状態は表を直接読んで確かめた |
| 再開のボタン | **実タップで G5 の本物の SQL** に届いた（世代 2→4） |
| サービス終了 | **偽物**。G3 の試験と同じく、表の行を直接 `ended` にした。アプリの終了の操作ではない |
| 画面の外での再開 | 別の端末の代わり。本人の JWT で G5 の同じ 2 つの呼び出しをスクリプトから行った |
| X の接続・再接続 | **偽物**。G4 の SQL と偽の token。**本物の X にも OAuth にもつないでいない**。`@g2_fake` は代役の表示 |
| 接続を切る | G3 の試験と同じ SQL。画面の操作ではない |
| ログイン切れ | `auth.sessions` の行を消して起こした |
| 通信エラー | 手元の Kong を止めて起こした |
| 予約の行 | 作成の画面を通さず、HTTP で入れた（前回タップで確認済み）。`a3reconf` の再確認待ちも HTTP で作った |
