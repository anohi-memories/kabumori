## 2. 記憶の状態の流れ（ソースから、G2-CC1）
- 記憶は `auth-flows.ts` の `outcomes`（処理の中だけ。端末には保存しない）。**時間の期限は無い**。32件を超えると、終わった物のうち一番古い物から消える。処理中の物は消さない。アプリの処理が新しくなれば空になる。
- 消す関数 `forgetAuthCallbackOutcomes()` は製品から呼ばれない（#419 CB3）。ログアウト・再ログインでも残る。
- 読み手は二つだけ:
  1. アプリ内ブラウザーの往復（`roundTrip`）: いつも**自分の flow id** を期待して呼ぶ。古い戻りは flow id の違いか、記憶の「どの流れか」の違いで拒否される。→ **古い成功がこの道に返ることは無い**（G2-CC2）。
  2. 深いリンクの受け口（`AuthProvider`）: 期待なしで呼ぶが、**失敗だけを表示**し、成功は捨てる。表示はログイン画面だけで、認証の出来事が起きるたびに消える。
- したがって、記憶に残った古い**成功**が画面に出る道は無い。出うるのは古い**失敗**の文言（「ログインを完了できませんでした」等）だけで、その戻りについては本当のこと。**CB3 は P3 に上げない**。

## 4. 受入条件（未確認の結果や別の人の成功を表示しないために）
ログインの戻り（現状で満たす。変更時の基準）:
1. アプリ内ブラウザーの往復は、自分の flow id の戻りしか完了しない（記憶に残った別の流れの成功を返さない）。
2. 深いリンクの受け口は、成功を画面に出さず、セッションも作らない（記憶から返った成功も同じ）。
3. 記憶が消えた後の再配達は、SDK とサーバーの本当の答え（拒否）を返し、成功にしない。
4. 投稿用の戻り（oauth-callback）は、ログインの入口では何も送らない。

X 接続（G4-18 の修正の受入条件。G2-CB5 の引き継ぎと同じ向き）:
1. 交換を送る直前に、今のログインの人とセッションが開始時と同じかを確かめ、違う・ログアウト中なら**交換を送らない**（G2-CB5・G2-CB6・G2-CX2 の古い token）。
2. 「接続しました」と `onConnected` は、成功の答えを受け取った時点でも同じ確認を通った場合だけ。
3. 取り消し・期限切れ・サーバーの拒否・形の崩れた答えでは、どの順序でも「接続しました」を出さない（G2-CX1・CX3 は現状で満たす）。
4. 同じ人の新しいセッションで続けてよいか（古い token を使わず新しい token で送り直すか、やり直させるか）は G4 が決める。サーバーがログアウト済みの token を受け付けるかは実環境で未確認（UNKNOWN）。

## 5. 見つかったこと
