## 1. #410 の仕組み（ソースの順序）
1. 送信開始: `runSend` が端末の記録（in_flight）とメモリ（本文つき）を書き、**返事待ちの登録**（`inflight.begin`）をしてから送信の口を呼ぶ。
2. 返事: メモリと端末の記録を答えに合わせて更新し**終えてから**、`inflight.end` で待っている画面に知らせる。
3. 返事待ちの間に開いた画面（作り直し・開き直し）は、メモリが本文つきの in_flight で、登録が「まだ出ている」なら **「送信中」の状態から始まり**（`createSendingState`）、`inflight.wait` で本当の答えを待って反映する。
4. 画面の区切りは `userId:sessionMark`（#398）。ログアウト中は `signed-out`。
