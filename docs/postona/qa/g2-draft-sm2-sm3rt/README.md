## 1. 仕組み（ソース、#468）
- 画面は「人 ＋ ログインの印（`last_sign_in_at`）」を鍵に作られる（`manual-publish.tsx` の route、#398）。印が変わると画面は作り直される。
- 下書きは印と一緒に保存され、印が違えば復元せず保存場所から消す（`manual-publish-draft-store.ts`）。
- 下書きの保存は、書き込みと削除を**頼まれた順に1つずつ**行う（G1 の試験 "writes and removals are applied strictly in the order asked"）。
- 前提（MOCK、NOT_VERIFIED）: `last_sign_in_at` は人ごとの値で、同じ人が別の端末でログインすると、この端末のトークン更新でも新しい値になる（SM2 の前提）。そのため、この端末から見ると「別の端末のログインによる更新」と「新しいログイン」が区別できない。

## 3. 分類
- SM2（P3、印の選定 G5／採用 G1）・SM3R-T（P3、G1・G5）は**既知・OPEN**。保存の側も消えること、確認の段階も消えることを記録した（新しい指摘にはしない）。
- 新しい確定した問題は無い。保存の途中・復元の途中の順序では、古い本文は戻らない（PASS）。
- 参考: G2 #470 の受入条件（退会の後片付けで下書きを消すとき、保存の途中の書き込みで復活する）は、後片付けが下書きの保存の**外から** AsyncStorage を直接消す場合の話。下書きの保存を通して消せば、この順に1つずつの仕組みで防げる（SR1 と同じ）。
- 実 Auth の `last_sign_in_at`・`session_id` の意味、実端末は NOT_VERIFIED。本番 NO_GO。
- 別の未解決のまま: SM4・SM4-D、G2-UC1・SN5・RK3、Threads の G2-T1・T2・T1-X、G4 #426 の安全レビュー、iOS 27 の標準ビルド、識別名 G2-ID1・ID5、Android 実機。
