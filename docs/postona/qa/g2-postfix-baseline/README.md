## 1. なぜ作ったか
#380・#394 の負例の確認は、元の行の文字列（例 `key={userId ?? 'signed-out'}`）を探して置き換えていた。G1 #398 でその行が変わり、「直った問題の正しい反転」と「目印が古いだけの失敗」が混ざった。新しい試験では次のようにした。
- 負例の確認を **TypeScript の構文木で書き換える**: 画面の区切りの `key` 属性、`sessionMark` 属性、「前回と同じ内容」の `<Text>` を出す条件、復元の `.then` 内の cancel の確認、`decideRestore` の印の確認。行が変わっても同じ意味の場所を見つけ、見つかった数（ちょうど1つ）も確かめる。
- 直った問題は「直っている」と確かめ、未修正の問題は引き続き FINDING として見つけ続ける。

## 2. 試験の中身
| 種類 | ID | 内容 |
|---|---|---|
| FIXED | SM1 | 使える印が無いと何も保存せず、新しいセッションにも戻らない |
| FIXED | SM3 | 同じ人が開いたまま再ログインすると画面が作り直され、古い文章は表示も保存（新しい印で）もされない |
| FIXED | X1 | 初回の送信では「前回と同じ内容・同じ送信ID」が出ない |
| FIXED | HOLD | ログアウト→ログインで戻らない／印が変わらない更新では文章が残る／復元の読み込み中に消えたアカウントの下書きは戻らない |
| FINDING | SM2 | 別の端末でのログイン（模擬）で、この端末の下書きが捨てられる |
| FINDING | SM3R-T | 印が変わる更新（模擬）で、開いている画面が作り直され、入力中の文章が消える（#398 から） |
| FINDING | SM3R-S | 同じことが送信の返事待ちに起きると「確認できません」になり、最初の返事の前に同じ番号の確認し直しが押せる（#398 から） |
| FINDING | SM4 | ログアウト後も本文が端末に残り、24時間の判定は読み込み時だけ |
| FINDING | SM4-D | 退会の後片付けが下書きを消さない（静的） |
| NC | 1〜5 | 構文木の書き換え: 区切りを人だけにする→SM3 が戻る／印を定数にする→再ログインで戻る／行の条件を「未解決があれば」に戻す→初回で出る／復元の cancel を外す→消えたアカウントの下書きが戻る／`decideRestore` から印の確認を外す→再ログインで戻る |
