# POSTONA personal MVP auth profile (G5-46, G5-47 — NOT applied, NOT in `supabase/migrations/`)

Production **NO_GO**. This is the G5 gate set for a 1 user / 1 workspace POSTONA. It does **without** the brand owner epoch (PR #285 / #303 / #457).

The design, the measured fail-closed table, the residual and the per-owner changes are in `docs/common-account/g5-46-postona-personal-mvp-auth.md`. R1-MVP and the token contract for G6 are in `docs/common-account/g5-47-postona-mvp-r1-personal-token.md`.

## Files

| File | What it is |
| --- | --- |
| `MVP_INSTALL.sql` | **One transaction.** Prerequisites (P1 chain, a stricter P3: no API write on `brand_memberships`, P4 auth, not a superuser; no owner epoch), then:<br>• S2-2 (bundle part 60);<br>• S2-1 T13 (part 70);<br>• the S2-3 predicate only (part 50 slices);<br>• GC (part 10 slice);<br>• the new MV (`parts/M10`);<br>• R1-MVP (`parts/M20`, G5-47);<br>• the owner-only postcondition. |
| `MVP_ROLLBACK.sql` | **One transaction.** Drops R1-MVP (only the MVP body), MV, the S2-3 predicate and GC (each refuses while another function names it or a dependency is recorded), then bundle R60 / R70. |
| `parts/M10_personal_worker_verdict.sql`, `parts/RM10_…_rollback.sql` | New SQL: MV `private.postona_personal_worker_verdict(uuid,text,text,bigint)`. |
| `parts/M20_personal_authorization_verdict.sql`, `parts/RM20_…_rollback.sql` | New SQL (G5-47): R1-MVP `public.common_account_authorization_verdict(text,text,text)`, the R1 v1 wire with `owner_epoch = g5pv:<lifecycle_version>`. Shipped **owner-only**: the reviewed R1 ACL (`authenticated`) is the bundled review's decision. |

Both entrypoints are generated by `supabase/tests/postona_personal_mvp_auth_build.py`:
- every bundle source is checked by git blob id;
- every slice is checked by its first and last line;
- `--check` re-derives both byte for byte.

## Apply / withdraw (procedure)

- **Apply** as the lifecycle owner (never a superuser):
  ```
  psql -v ON_ERROR_STOP=1 -f MVP_INSTALL.sql
  ```
  A second run refuses.
- **Withdraw:** remove the consumers first, then `MVP_ROLLBACK.sql`.
- **Profiles exclude each other.** This profile and `../postona_personal_auth_migration/` (G5-42) each refuse on top of the other. To switch, roll back one and install the other.
